# 域名与部署扩展说明

当前前端用 `/`、`/learn`、`/admin` 区分官网、学员端和管理端。上线初期可以共用一个站点；流量或权限要求增长后，再把同一个前端按域名分流，或拆成单独构建目标。

| 域名建议 | 服务 | 说明 |
| --- | --- | --- |
| `example.com` / `www.example.com` | `apps/web` 官网 | 品牌介绍、课程目录、转化入口 |
| `learn.example.com` | `apps/web` 学员端 | 会员中心、课程进度、学习记录 |
| `admin.example.com` | `apps/web` 管理端 | 课程、会员、内容与运营管理；必须添加身份认证和权限控制 |
| `api.example.com` | `apps/api` | 用户、会员、课程、订单等业务 API |
| `ai.example.com` | `apps/ai` | 模型代理、AI 内容任务、异步生成接口 |

## 部署步骤（主机/容器）

1. 选择支持 Node.js 22 与 Python 3.12 的主机或容器平台，部署 `web`、`api`、`ai` 三个服务。
2. DNS 添加 A/AAAA 或 CNAME 记录，分别指向边缘代理/负载均衡；确认域名解析后申请 TLS 证书。
3. 配置反向代理：前端域名到 Web；`api.*` 到 `api:4000`；`ai.*` 到 `ai:8001`。跨域访问时将 API 的 `WEB_ORIGINS` 限定为实际前端域名。
4. 配置 `.env` 中的公开 URL、密钥及模型供应商变量。不要将 `.env` 或密钥提交到 Git。
5. 中国大陆境内提供公开网站服务时，依据服务器所在地、接入方式和业务类型完成适用的备案与合规要求；当前示例没有代为绑定域名或部署。

## 上线前必须补齐

- PostgreSQL 数据模型、迁移、备份和真实课程/会员数据。
- 登录、密码重置、管理员 RBAC、会话安全、操作审计、验证码与限流。
- 支付订单、退款和支付回调验签；不要只依赖前端支付状态。
- 视频存储、鉴权播放、签名 URL 和内容版权管理。
- AI 供应商适配、超时/重试、成本限额、内容审核和敏感数据策略。
- 医美广告内容审核流程；不输出医疗诊断或未经证实的疗效承诺。
- 监控、日志脱敏、告警、备份恢复和安全扫描。
